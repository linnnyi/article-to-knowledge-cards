# make-knowledge-cards

一个面向 Codex 的知识卡片 Skill：把用户粘贴的文章或本地 Markdown/TXT 文本整理成准确、互不重复的知识卡片。

## 项目解决什么问题

长文章、学习笔记和研究材料往往包含大量背景、重复表述和次要细节，直接复习时不容易抓住重点。本项目把受支持的文本压缩成少量独立知识卡片，帮助读者快速理解、复习和检验核心知识。

生成过程以原文为边界：不补充外部知识，不编造例子、数字或因果关系，也不为了达到卡片数量而拆分重复内容或强行凑数。

## 主要功能

- 支持用户直接粘贴的文本，以及本地 `.md`、`.markdown`、`.txt` 文件。
- 默认生成 5～8 张知识卡片，最多 8 张；若原文支持的重要知识点不足 5 个，则按实际数量输出并说明未强行补足。
- 每张卡片包含标题、核心知识、简明解释，以及例子或自测问题。
- 一张卡片只讲一个知识点，并合并近似或重复内容。
- 根据解释型文章、操作型文章、观点或论证型文章、短笔记或清单分别取舍内容。
- 保留原文的范围、条件、概率和语气；观点型内容会标明作者主张，不升级为普遍事实。
- 优先使用原文中的例子；原文没有合适例子时，使用不依赖外部知识的自测问题。
- 如果原文没有可提炼的实质知识，不生成空泛卡片。

当前不支持网页抓取、PDF、Anki 导出和图形界面。

## 安装方法

将整个 `make-knowledge-cards` 文件夹放入 Codex 的 skills 目录：

- 默认路径：`~/.codex/skills/make-knowledge-cards`
- Windows：`%USERPROFILE%\.codex\skills\make-knowledge-cards`
- 如果设置了 `CODEX_HOME`：`$CODEX_HOME/skills/make-knowledge-cards`

重新加载 Codex 后，即可通过 `$make-knowledge-cards` 显式调用。本 Skill 不需要额外脚本或第三方运行时。

## 使用方法

处理粘贴文本：

```text
$make-knowledge-cards 把下面这篇文章整理成知识卡片：

<粘贴文章正文>
```

处理本地文件：

```text
$make-knowledge-cards 读取 notes/article.md，把它转换成知识卡片。
```

也可以在请求中指定输出语言、字段顺序或格式。Skill 会保留四项卡片信息和原文事实边界。遇到网页、PDF、Anki 或图形界面输入时，请改为粘贴正文或提供 Markdown/TXT 文件。

## 输入输出示例

输入：

```text
会议纪要应围绕会议作出的决定和关键理由组织，而不是按发言顺序复述讨论过程。开始讨论每个议题前，先确认本轮要作出什么决定；如果只是信息同步，就明确记为不需要决定。每个行动项都要写明负责人、完成期限和验收条件。若会上没有确定负责人，应把“确定负责人”本身列为行动项，而不是默认由发起人承担。下次会议开始时，先检查上次行动项的完成情况，再处理新议题。
```

输出：

```markdown
共 5 张知识卡片。

### 01｜会议纪要应围绕决定和关键理由组织

**核心知识**：会议纪要应围绕会议作出的决定和关键理由组织，而不是按发言顺序复述讨论过程。

**简明解释**：文章要求用决定和理由作为纪要的组织线索，避免把讨论过程本身当作主要记录对象。

**例子或自测**：自测：纪要应以发言顺序为主，还是以决定和关键理由为主？（答案：以决定和关键理由为主。）

### 02｜讨论议题前先确认需要作出的决定

**核心知识**：开始讨论每个议题前，应先确认本轮要作出什么决定。

**简明解释**：如果该议题只是信息同步，文章要求明确记为不需要决定。这一规则区分了需要决策的议题和只作说明的议题。

**例子或自测**：自测：某个议题只是信息同步时，应如何记录？（答案：明确记为不需要决定。）

### 03｜行动项要写清负责人、期限和验收条件

**核心知识**：每个行动项都要写明负责人、完成期限和验收条件。

**简明解释**：文章把这三项作为行动项的明确要素，使行动项包含责任、时间和完成标准。

**例子或自测**：自测：一个完整的行动项需要写明哪三项内容？（答案：负责人、完成期限和验收条件。）

### 04｜没有负责人时，把确定负责人列为行动项

**核心知识**：若会上没有确定负责人，应把“确定负责人”本身列为行动项，而不是默认由发起人承担。

**简明解释**：文章不允许用默认承担来填补缺失的责任分配，而是要求把负责人仍未确定这一事项继续作为待办处理。

**例子或自测**：自测：会上没有确定负责人时，能否默认由发起人承担？（答案：不能，应把确定负责人列为行动项。）

### 05｜下次会议先检查上次行动项

**核心知识**：下次会议开始时，应先检查上次行动项的完成情况，再处理新议题。

**简明解释**：文章明确了检查旧行动项与新议题之间的顺序：先回顾上次行动项，再进入新议题。

**例子或自测**：自测：新会议应直接开始讨论新议题，还是先检查上次行动项？（答案：先检查上次行动项。）
```
